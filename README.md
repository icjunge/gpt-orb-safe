# GPT 悬浮球 · 2.5.2

Windows 10 / 11（64 位）常驻桌面的 Codex 额度监控工具。**通过官方 Codex CLI 读取：每隔自选的分钟数查询额度，关闭浏览器和用量页后也能刷新，不会临时打开页面。** 浏览器扩展保留为手动选择的备用来源。

悬浮球只查询用量，不发起模型任务，不代发对话，不自动消耗重置次数。登录由官方 Codex 管理；悬浮球不读取或复制 `auth.json`、Cookie、密码或访问令牌。

**2.5.2：更小的透明百分比圆球。** 常态 48 像素，悬停轻微放大至 56 像素，球内始终只显示剩余百分比；额度窗口、来源、历史状态和重置时间放入鼠标悬停提示。点击查看详情，拖动移动。圆球显式关闭会造成方块的系统底材，使用轻浅的半透明圆面；详情面板保留原有系统材质。

`npm run extension:update` 只更新浏览器扩展，不会更新桌面外观；源码提交也不等于正式安装包已发布。

已有 2.4.1 安装版无需再次下载测试安装器。正式发布后，在「设置 → 版本与更新 → 检查更新」下载经原公钥验证的新版本，再点「重启并更新」；保留已开启的自动检查时，也会在后台检查。发布流水线的审批未完成前，客户端不会收到新版。

## 第一次使用本机 Codex 读取

1. 更新到可信渠道正式发布的 2.5.2 桌面安装版；已有签名更新能力的安装版可在「版本与更新」检查，下载后点击「重启并更新」。从旧免安装包迁移需运行安装包一次，新旧程序不要同时运行。若安装包尚未发布，可按下节运行已取得的源码。
2. 在 Windows PowerShell 安装 **OpenAI 官方 Codex CLI**，然后使用与网页版相同的 ChatGPT 账号完成官方登录：

   ```powershell
   npm.cmd install -g @openai/codex
   if ($LASTEXITCODE -eq 0) { codex.cmd login }
   ```

   Windows 使用 `.cmd` 入口，避免 PowerShell 对 `.ps1` 脚本的执行策略拦截，无需更改策略。安装命令需要 Node.js/npm；已经安装并登录 CLI 的用户无需重复操作。安装后若当前终端找不到 `codex`，重新打开 PowerShell；悬浮球也需重新启动以取得更新后的环境。只在官方登录流程中授权，不向悬浮球填写账号密码、设备授权码或令牌。使用 API Key 的 CLI 配置不等于 ChatGPT 订阅登录，可能无法返回这里需要的额度。
3. 在悬浮球设置的「数据来源」选择「本机 Codex」，设置刷新间隔（整数 **1–1440 分钟，默认 5**），点击「保存」，再点击「开启读取」。工具提供「复制安装命令」及「安装说明」入口，由你在终端执行；它不会自动安装、登录或修改账号配置。
4. 点击「立即刷新」，检查来源、成功读取时间及额度窗口。此后只需保持悬浮球运行，浏览器可以关闭。登录失效时按提示重新使用官方 CLI 登录。

CLI 首次登录可能打开浏览器；这是官方登录流程，之后的用量刷新不通过临时网页。官方 CLI 是外部依赖，不随悬浮球打包；悬浮球不会在后台自动安装或升级它。安装和登录说明：[Codex CLI](https://learn.chatgpt.com/docs/codex/cli)、[官方认证说明](https://learn.chatgpt.com/docs/auth)。

## 已有源码时直接运行新版

先退出已安装的旧悬浮球，避免旧进程占用同一运行实例。在已经克隆的仓库目录运行（将示例路径替换为实际位置）：

```powershell
cd C:\path\to\gpt-orb-safe
git pull --ff-only
if ($LASTEXITCODE -eq 0) {
    npm ci
    if ($LASTEXITCODE -eq 0) { npm start }
}
```

`npm ci` 按 lockfile 安装依赖及 Electron 运行时，需要可用网络。这里不要加 `--ignore-scripts`：那会跳过 Electron 的运行时安装。源码运行不改变已安装版本，也不提供安装版自动更新；以后要使用应用内更新，仍需正式签名安装版。这是运行可信本地源码的方式，不经过安装包签名验证。

## 数据含义与刷新行为

| 显示项 | 本机 Codex 来源的含义 |
|---|---|
| 额度窗口 | 官方 `account/rateLimits/read` 返回的已用 / 剩余比例；各窗口独立显示，不相加 |
| 重置倒计时 | 按官方返回的重置时刻计算；归零不会自行恢复额度 |
| 剩余重置次数 | 仅在官方响应明确提供时显示，未知为「—」；工具不执行重置 |
| 独立额度 | 仅展示实际返回的独立额度记录，包括可识别的 Spark 记录；不凭模型名称编造窗口 |
| Token 统计 | 协议支持时读取 `account/usage/read` 的服务端统计，显示返回范围的累计及最新日桶；不把最新日桶冒充本机今日 |
| 成功读取时间 | 表示本次查询成功，不代表官方服务器的统计刚刚更新 |

Token 统计按当前官方 CLI 的协议能力读取，不支持时隐藏 Token 模块；可在设置的数据说明中了解统计范围。它不是扫描本机 Codex 会话日志得到的记录，也不承诺覆盖全部普通 ChatGPT 对话、所有设备历史或 API 账单。官方未提供、版本不支持或无法识别的字段保持未知；不能用额度百分比反推 Token 总数。

新安装及从旧版迁移后默认选择本机 Codex，但首次不会自动读取；需要你主动开启。启用状态与间隔会保留，之后启动悬浮球按已保存设置继续读取，无需浏览器配对。可随时点击「暂停」，不会退出官方 Codex 登录。切换到其他来源后，切回本机模式需再次开启。刷新间隔可在桌面设置调整，也可立即查询。电脑睡眠、离线、CLI 缺失、登录过期或服务端延迟会影响读取；失败会显示原因并保留最近一次有效记录及其成功时间，不用失败尝试伪造新数据。检测到退出登录或账号变化时会清除旧账号读数，避免串账号。切换来源时明确标记当前来源，不把浏览器与 CLI 的数字拼成一份账号总量。

官方 App Server 接口目前具有实验性，版本变化可能影响兼容性。工具只使用固定的查询请求，解析不了的结构不会当作成功额度。详情见 [App Server 官方文档](https://learn.chatgpt.com/docs/app-server)。

## 浏览器同步作为备用来源

需要网页读取时，先在桌面选择「浏览器扩展」来源，再按以下步骤连接。两种来源由用户选择，不因一次 CLI 失败就自动切换到网页。

1. 在桌面点击「打开固定扩展文件夹」，通常为 `%APPDATA%\GPT Usage Orb Safe\Browser-Extension`，以实际打开的位置为准。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启「开发者模式」，加载该目录。所选目录必须直接包含 `manifest.json`。此前加载 `Downloads` 中旧目录的用户需移除旧项并迁移一次；不要双击 `popup.html`。
3. 打开 <https://chatgpt.com/settings/usage?tab=overview>，只在官方网站完成登录。复制悬浮球当前配对码，从浏览器工具栏打开扩展，粘贴后点击「连接并开始读取」。配对码只允许本机数字同步，不是 GPT 登录码。

当前页面模式需保留用量页。备用的「后台定时刷新」可设 1–1440 分钟、默认 5，主动开启时申请 `https://chatgpt.com/*` 可选来源权限。每轮创建非活动临时用量标签页，读取后仅关闭本轮创建且未被用户接管的页面。浏览器授权覆盖整个来源，代码只在两个精确用量路径采集。点击「关闭并撤销授权」停止任务并撤销该权限。

**只有浏览器备用模式需要浏览器保持运行。** 配对及后台启用状态仅保留当前会话，桌面退出、浏览器重启或扩展重载后需重新配对；扩展重启后需重新开启定时任务。若从旧版切换到本机 Codex，建议先在扩展点击「关闭并撤销授权」，避免之前的扩展任务继续尝试打开页面。CLI 读取不需要浏览器扩展权限。

页面布局无法识别时，可在扩展手动填写页面明确显示的数字，未知项留空。填写的是**已用百分比**：剩余 80% 应填已用 20%。手动提交后暂停扩展自动读取，桌面标记为「人工记录」。页面读取时间不代表官方统计更新时间。

### 只维护浏览器扩展

```powershell
git pull --ff-only
if ($LASTEXITCODE -eq 0) { npm run extension:update }
```

此命令不需要 `npm ci`，只同步固定扩展目录，不启动桌面、不自动重载浏览器。随后在扩展管理页重新加载并确认 2.5.2，重新配对。它**不更新桌面，也不启用本机 Codex 来源**。2.1.1 等旧桌面不认识新版扩展清单，可能提示目录更新失败，但会保留现有文件；桌面升级后使用新版校验器。

## 玻璃效果与兼容性

设置中的「玻璃着色」从清透调至深色，只改变原生材质上的染色。真正的桌面模糊由 Windows DWM 提供；网页 CSS blur 不能跨窗口模糊桌面。本工具不会截图桌面来模拟效果，不新增屏幕采集权限。

圆球始终使用透明窗口与圆形区域，不再启用 Acrylic，也不再等待 GPU 检测结果。这样避免部分电脑上系统底材绘制出矩形底色；球面可透出后方应用颜色，但不宣称具有跨窗口模糊。详情面板仍在受支持的 Windows 11 上请求系统材质，实际模糊受系统透明效果、省电和驱动等条件影响。减少透明度或高对比度时使用清晰实色。

字体在 Apple 平台优先使用系统字体；Windows 内置 Inter（SIL Open Font License），配合等宽数字、适中的字重与紧凑字距。Apple SF Pro 未被打包，Windows 的原生鼠标提示使用系统提示字体。字体来源与许可证见 `assets/fonts/`。

## 日常使用和应用更新

悬浮球始终只显示剩余百分比，悬停或键盘聚焦后轻微放大，移开缩回；额度窗口、来源和倒计时在鼠标悬停提示中查看。拖动调整位置，点击展开 / 收起详情面板。托盘菜单和 `Ctrl + Alt + G` 可找回面板。置顶、透明度、额度提醒和开机启动可在设置中调整，开机启动默认关闭。

已配置发布源的 Windows 安装版默认在启动约 10 秒后检查更新，之后每 6 小时检查一次，也可手动检查或关闭自动检查。程序验证 Ed25519 发布签名，再下载并校验安装包版本、长度及哈希；准备好后由你点击「重启并更新」。普通退出不会自动安装待更新包，网络或校验失败不影响当前版本继续运行。

更新包含桌面、Electron 运行时及备用浏览器扩展，不包含官方 Codex CLI。显示设置和位置保留；浏览器配对码不持久保存。固定目录中的扩展更新后需在浏览器手动重新加载；只使用本机 Codex 时无需加载扩展。

只有已配置仓库与公钥的安装版能在线更新。开发运行、旧免安装包、未配置发布源的安装包不具备该能力；不要向 `update-config.json` 填入账号令牌。源码提交、版本标签、草稿 Release 均不等于已发布正式更新。

安装前备份用户数据目录中的 `preferences.json` 到 `recovery`。**这是设置备份，不是完整程序快照或 NSIS 安装失败后的自动回滚。** 安装中断时用同版本或较新可信安装包修复；手动恢复设置前退出程序，再将选定备份复制为 `preferences.json`。

## 账号与安全边界

- 悬浮球启动本机已安装的官方 Codex `app-server`，通过标准输入 / 输出发送固定查询请求。它不读取、复制或自行保存账号凭据，不记录原始 RPC 响应；没有聊天、文件操作、模型任务或重置额度入口。
- **官方 Codex CLI 仍会使用本机登录状态，并可能续期及更新自己的凭据。** 凭据存放在文件还是系统凭据库，取决于官方 CLI 与既有配置；不能承诺天然加密。请只使用可信官方 CLI，并保护本机用户账号。停止悬浮球读取不等于退出官方登录；如需退出，可自行运行 `codex.cmd logout`。
- 浏览器备用扩展不读取 Cookie 或聊天内容，数值只发往 `127.0.0.1:43861`，接收端校验扩展来源、会话配对码及字段。网页模式的官方登录仍由浏览器保管。
- 安装更新只访问固定的 GitHub Release 来源及资源域名，请求不包含用量或账号凭据，也不要求客户端 GitHub 登录或 PAT。发布私钥不进入应用；现有签名信任链保持不变。
- 没有自建云用量同步或额外遥测。**Ed25519 更新签名不等于 Windows Authenticode 发布者证书**；当前安装包没有 Windows 发布者签名，系统可能提示未知发布者。

本工具不是 OpenAI 官方应用，不能防御已经控制本机、CLI 或浏览器的恶意软件。完整边界见 [SECURITY.md](SECURITY.md)。若曾使用 1.0.0 的登录功能，仍需单独确认旧版退出或通过官方账号会话管理撤销；2.x 不读取、复用或删除那份旧凭据。

## 卸载与验证范围

卸载前关闭开机启动并退出悬浮球；不再使用浏览器模式时移除扩展，然后在 Windows「已安装的应用」卸载。默认保留用户目录中的显示设置、扩展与备份，确认不再需要后可删除。卸载悬浮球不会卸载 Codex CLI，也不会退出 CLI 或浏览器中的官方账号。

自动测试检查固定 RPC 请求、额度数据校验、异常处理、来源切换、刷新状态及既有更新边界。CLI 协议测试使用合成进程与响应，不接触真实登录。已有页面 DOM、离屏界面、MV3 传输测试不等于完整 Chrome / Edge 权限流程。**实体 Windows 安装 / 升级、真实账号 CLI 返回值及官方登录流程仍需实机验收。** 不把模拟测试或构建成功写成这些实机测试通过。

## 源码、打包与发布

代码仓库：<https://github.com/icjunge/gpt-orb-safe>。开发需要 Node.js 22.12+，执行 `npm ci`、`npm test`，再用 `npm start` 启动。Windows 环境执行 `npm run build:win` 生成 NSIS 安装包；运行安装后的桌面不需要 Node.js 或 Python，但使用 npm 安装官方 CLI 需要 Node.js/npm。

```sh
python scripts/package_windows.py --source-only --extension-zip --output dist
```

维护者按 [RELEASE.md](RELEASE.md) 使用既有仓库、公钥、发布私钥与受保护签名流程。已完成初始化的仓库不要重新生成密钥。GitHub Actions 构建及草稿发布不代表正式 Release 已公开。
